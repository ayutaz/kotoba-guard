# Security policy

Kotoba Guard is in development; no stable release is currently supported. Do not put private text, tokens or credentials in a public issue. When a repository security advisory channel becomes available, report vulnerabilities privately through it. Until then, do not publish exploit details or contact third parties on behalf of the project without authorization.

Security boundaries: explicit site access, sensitive-input exclusion, extension-owned local inference, validated messages, no input persistence or telemetry, bundled code and models. See [threat model](docs/threat-model.md), [design](docs/security-design.md), and [verified status](docs/status.md). Document the source commit, browser/OS version, minimal synthetic reproduction and observed impact when reporting a bug.
