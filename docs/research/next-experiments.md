## 独立した実用日本語評価の設計

文体は業務メール、SNS・短文口語、技術文の3層。pilot後の最終目標は各文体400正常＋400誤り、計2,400例（正常1,200例）。これは取得済みの件数ではない。テンプレートの語句置換を独立した大量サンプルとして数えず、著作者・文書・テンプレート単位のcluster数も報告する。

データは、プロジェクトで新規作成した非機密文章、明示的な再利用条件を確認できる文章、既に許諾された文章を使う。非公開ユーザー文章、実サービスからの無許可収集、条件不明の転載は使わない。本文ごとにsource ID、著作者または生成方法、取得日、ライセンス、評価・再配布の可否、文体、document/template cluster、split、hashを記録する。モデルの学習データへの露出が不明ならunknownとする。

controlled層は正常文へseed固定の変異を加え、変異前後・操作・ラベル・code point spanを保存する。自然な誤りかを検証していない合成例を、自然発生誤りや人間の品質判断の証拠にしない。practical層はモデル出力と独立した根拠のあるgoldを必要とする。独立注釈・第三者の既存goldが得られない場合はpractical受け入れを未検証とし、AIの自己判定だけで正常文や誤りの正解を確定しない。ユーザーに注釈作業を要求したり、外注・課金を開始したりしない。

分割は文単位でなく文書・著作者・テンプレート単位とする。既存JWTDのpre/post本文・ページIDとNFC/空白正規化の重複を照合し、near-duplicateも記録する。正常・誤りの対と同一テンプレートを別splitへ分けない。新しいtestの本文・gold・採点仕様のSHAと選択条件を推論前に固定し、testを見て閾値を選び直さない。改善に使った集合はdevまたは回帰へ移し、新しい独立testを用意する。

goldは元文のUnicode code point半開区間を保存し、UTF-16へ決定的に変換する。0幅脱字、改行、結合文字、絵文字を含める。誤り種別、位置、文脈不足、口語・固有名詞、曖昧性を記録し、判断不能は別集計する。モデル予測を見てgoldを変更しない。

## 指標と受け入れ

主指標の定義を測定前に固定し、一対一対応のラベル付きeventとstrict span、containment、token-projected span、token分類を併記する。文体別とcontrolled/practical別のmicro/macroを分け、正常文誤検出は「1件以上指摘した正常文／全正常文」とする。Wilson区間と文書clusterによるbootstrap区間を保存し、tokenを独立標本として区間を狭めない。

当初の点推定目標はPrecision95%以上、Recall80%以上、正常文誤検出2%以下、正常文1,000例以上、量子化F1低下0.01以内。95%区間も併記する。区間下限までの合格を新たに主張する場合は、別の事前登録した厳格判定として扱い、実行後に基準を選ばない。正常文・goldの独立性を確保できなければ、件数だけ満たしても実用精度合格にはしない。

欠落行、split重複、権利不明、非有限logit、shape/ID/offset不一致、系列長超過を検出したら原因を直すまで評価を停止する。実用精度未達なら公開移行を止め、参照能力・量子化差・ブラウザ差・製品表示差を分けて報告する。追加学習・別モデル比較は次の具体案として判断し、自動で70Mへ切り替えない。

CPU推論とブラウザ性能計測は直列で行い、cacheを再利用する場合はモデル・dataset・tokenizer・protocol・採点コード・logitsのSHAを照合する。新規実験の結果は未測定のままにし、既存値を付け替えない。

## 事前固定する追加条件

Bのfixed64は数値・span一致用であり、速度測定の128 token入力とは別。速度は既存benchmarkと同じ3 warmup＋20 samplesを使い、CPU・browser/ORT版・WASM thread数・COOP/COEP・SharedArrayBuffer・実効thread数を保存する。新候補の採用には、他の重い処理を止めた3回のfresh browser実行すべてで128 token p50<=100ms・p95<=250msを満たすことを要求する。候補ごとにcold start・長文・資源も別記録し、1回だけの好結果を選ばない。

practical層の新規注釈は2名以上が予測を見ずに独立実施し、一致率・合意率と不一致時の判定手順を先に固定する。既存の第三者goldを使う場合はその作成・検証方法を確認する。どちらも確保できない場合、practicalの受け入れは未検証とする。ユーザーへ追加作業を課したり、外注を開始したりしない。

誤りの来歴はnatural、authored_mutation、controlledを区別して保存・集計する。許諾済み自然文を人為的に誤らせた例を自然発生誤りへ分類しない。自然発生誤りの独立goldが得られない場合、「自然発生誤りに対する精度は未検証」と明記する。
