# ADR-0008: 30Mモデルの公開受け入れを保留する

日付: 2026-11-27。判断: 開発用実行経路を維持し、正式公開への移行は保留。

## 根拠

固定revision `8d640720bddeb64c89dc1fa7780c3ea29fa523e8` の参照モデルは、JWTD公式test採用10,872例でPrecision74.57%、Recall63.32%、正常文誤検出469/5,436（8.63%）だった。開発用で選べる閾値にも、Precision95%・Recall80%・正常文誤検出2%以下を同時に満たす点はない。これはこのデータと採点仕様での結果であり、メールやSNSへの一般化を測った結果ではない。

最新のweight-only候補（Gather後にembeddingを逆量子化、モデルSHA `4cd8f3a048ec403c1aa521da1e00e38c5b24414ffa97a6ffb325de15b68d9ee7`）も開発用2,000例の新規推論でPrecision78.90%、Recall65.53%、正常文誤検出56/1,000。参照からのF1低下0.0002371は量子化の許容値以内だが、製品精度は未達。数値変換の改善と参照モデルの検出能力を分けて判断する。

候補のWASM128 tokenは1 threadでp50 187ms。隔離4-thread実験はp50 96.82msの後、再測定114.595msとなった。最初の実行はunit testとの重複可能性もあるため、好都合な1回を採用理由にしない。offscreen/workerでの4-thread数値一致と通常拡張経路は未検証であり、現段階で配布モデルを置き換えない。

ラベル対応・offset復元の取り違えを支持する根拠は見つかっていない。[採点診断](../research/accuracy-diagnosis.md)に記録した包含一致や曖昧diffの最良解釈は、むしろ楽観的な集計になりうる。精度未達を採点の厳しさだけで説明しない。

## 選択肢と判断

追加の[全confidence閾値診断](../research/confidence-frontier.md)をclean `d9c44d6`で完了した。固定development-v1の全予測状態（PyTorch/FP32/FP16各1,340点、QUInt8 1,332点）でも3目標の同時達成は0。参照の最大Recallは687/1,027（66.89%）で、閾値の粗さがRecall80%未達の原因という仮説は否定された。最大F1点も製品設定へ採用しない。独立goldやラベル別校正、別モデルの評価ではなく、30Mを開発経路として維持して公開保留にする判断は変わらない。

| 選択肢                                  | 利点                                             | 不足する根拠・制約                                                             | 判断                                             |
| --------------------------------------- | ------------------------------------------------ | ------------------------------------------------------------------------------ | ------------------------------------------------ |
| 固定30Mモデルの変換・推論経路を改善する | 既存のモデル・ライセンス・サイズ方針を維持できる | 量子化差を減らしても参照自体の精度未達は残る                                   | ローカル技術検証を継続。精度改善の代替とはしない |
| confidence閾値を上げる                  | 開発用の正常文誤検出が減る                       | Recall低下が大きく全基準を満たさない                                           | 公開合格の根拠にしない                           |
| 別モデルや追加学習を比較する            | 元モデルの能力を変える可能性がある               | 未測定。学習データの権利・独立評価・CPU/WASMの資源と配布サイズを再検証する必要 | 次の研究提案。未実行、採用決定なし               |
| 製品範囲・精度基準を変更する            | 利用場面を絞れる可能性がある                     | 当初の品質目標と異なる。実利用分布の独立評価が必要                             | 自動では変更しない。具体案と実測を揃えて判断する |

70M・辞書・修正生成を先に追加してP0の未達を覆わない。既知のtestを改善の選択に使う場合は回帰データへ移し、新しい独立評価を用意する。学習や新モデルの性能を推測で主張せず、課金・公開・認証変更の権限は拡張しない。

## 次段階への条件

ソースとモデルを固定した開発用成果物、失敗を含む評価、通信・資源・OS検証を揃え、`development_snapshot` としてレビュー可能にする。これはrelease candidateではない。独立評価で当初の精度基準を満たすまではMVP完成・正式公開へ移行しない。

証拠: `artifacts/corpus-evaluation/held-out-v1/evaluation.json`（ソース`af8cd94`）、`artifacts/candidate-evaluation/weight-only-after-gather-1d1bc73/candidate-evaluation.json`（ソース`1d1bc73`）。測定条件は[評価仕様](../evaluation-protocol.md)、[ベンチマーク](../benchmarks.md)に従う。

## 2026-11-28追記: 早期previewと正式受け入れ

正式公開保留と精度目標未達の判断は維持する。ユーザーは最適化を後工程へ延期し、
数値一致済みFP16保存候補の開発preview統合を優先した。sourceaea6cafのbuild/E2E7件は成功したが、
監査context cleanup失敗でZIP未生成。新モデルの一般精度は未評価で、旧QUInt8の精度を転用しない。
元の100ms速度目標・精度条件を達成扱いにせず、previewをM5完成/公開許可とはしない。
開発は停止中。[最新検証](../preview-validation.md)を参照。
